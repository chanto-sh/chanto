# Changelog

## Unreleased

## v0.1.12 (October 31, 2026)

- **Faster one-shot runs on Windows.** Each start launched a command to check that the sandbox works, even if the run never used the shell. A one-shot run now checks just before its first shell command, and that command waits for the answer, so the sandbox protects it as before. If the sandbox can't start, the warning now appears at that point too.
- **Shell commands on Windows.** With the sandbox on, which is the default, commands failed wherever Git Bash was installed, because Git Bash can't start inside the sandbox. They now run in PowerShell there, and the model is told so. Without Git Bash, commands failed in PowerShell with a parse error; that's fixed too. With the sandbox off, Git Bash is still used.
- **`ultra` effort, and `max` on recent OpenAI models.** `--effort ultra` (or `/think ultra`) asks for high reasoning and tells the model to delegate to subagents on its own, modelled on what Codex sends for Ultra. `max` now reaches GPT-5.6 and GPT-6 models through the Responses API; it used to be sent as `xhigh`.

## v0.1.11 (October 31, 2026)

- **Chanto's agent for web pages, on npm.** Each release now publishes `@chanto/web`: the agent loop and its file tools as WebAssembly, working on a project held in memory, with the model supplied by the page. It's what runs on chanto.sh/try. It's experimental, and its interface may change in any release. The release also attaches it as `chanto-web-vX.Y.Z.tgz`, covered by the signed checksums and build provenance like the CLI archives.
- **Faster start in big folders.** Before showing its first screen, Chanto looked through the whole folder it started in for env files whose values it masks, which took about half a second in a large folder (a directory of many projects, say). That search now runs in the background: each turn still picks up the files before its first model request, so nothing goes out unmasked. Started in a folder of 100,000 files, the first screen now appears as fast as in an empty one.
- **The right upgrade command on Homebrew.** When Chanto ran through Homebrew's link in its `bin` folder, the upgrade notice could suggest the install script instead of `brew upgrade chanto`. It now goes by where the binary really is.

## v0.1.10 (October 30, 2026)

- **Local models' tool calls.** With `tool_protocol = "text"`, a reply made only of JSON tool calls one after another (bare or in a code fence), as small local models often write them, now runs every call. Only a single bare call ran before, and a reply with several ran none. Any prose around them, or an object that isn't a call to a known tool, still means none run.
- **No login shell in sessions that run no commands.** Since 0.1.9, Chanto started your login shell during each session's first model reply, to capture your shell setup (PATH, aliases, functions) before the first Bash command. It did this even in sessions that never ran a command, and the shell could outlive a short session. It now starts when the model begins a Bash call. Sessions that only read, edit or answer never run your startup files. On GitHub's Ubuntu runner, that shell had raised the published 40-request benchmark's peak memory from 26 MB (0.1.8) to 57 MB. The first command still overlaps the capture with the rest of the model's reply, though no longer with all of it.

## v0.1.9 (October 30, 2026)

- **Long sessions stay fast.** Before every model request Chanto checks that each tool call's results sit right after it, and it used to take every result out and put it back even when they already did, shifting the whole transcript each time. A well-formed transcript is now left in place: a 400-turn session uses about 20% less CPU, and the saving grows with the session.
- **Lighter start on macOS.** Chanto no longer starts a `sandbox-exec` probe on every launch. It asks the kernel whether it already runs inside a sandbox, which is the only case where its own sandbox can fail to start, and runs the probe only then. That saves about 8 ms of CPU per launch.
- **Faster start with hosted models.** Chanto no longer waits for the model provider before showing its screen. It used to ask the provider's model list for the context window on every launch, and DeepSeek's list has none, so nothing was ever cached: about 0.6 s on each start, up to 4 s on a slow network. An answer without a window is now cached like any other, and a provider that doesn't answer quickly is asked in the background, with the first request waiting for it if it's still out. The first screen appears in about 140 ms instead of 770 ms.
- **Less memory and CPU per request.** Each model request used to copy the whole conversation's text several times (the published snapshot, the request, its redacted copy). Messages now share their text, so a copy is a reference count and only a message that changes is copied. On a 40-turn session of file reads, peak memory drops 11% (24.4 to 21.8 MB) and CPU per request 7%; on a 400-turn session, CPU drops 20%.
- **Faster shell commands.** Every Bash command used to define all the shell functions your startup files set up before running, about 20 ms each with nvm installed. They now load the first time a command calls one of them, so a command that doesn't (nearly all of them) skips that work: 47 to 26 ms per command in one measurement.
- **Quicker first shell command.** Chanto captures your shell's setup (PATH, aliases and functions from your startup files) while the model writes its first reply, instead of when the first command needs it. With busy startup files the first command in a session used to wait for that capture, 2.5 s in one measurement; it now waits for whatever the reply didn't cover, 0.5 s there.
- **Waiting on a background command.** `BashOutput` with `wait_secs` returned as soon as a command printed anything, so a test run printing a dot per test ended every wait at once and the model polled again and again: 60 polls and the full 30-minute limit in one benchmark task. It now waits until the output has settled for a few seconds, the command exits, or (with `filter`) a matching line appears.
- **Faster one-shot runs and requests.** A turn that only reads or answers no longer snapshots the project for `/rewind`: the snapshot is taken just before the first tool that can change files, so rewinding works as before. Model requests share one HTTP client instead of building one per provider, a model server on this machine skips the system proxy lookup, the machine is kept awake only once a turn has run for 20 seconds, and secret redaction runs a token pattern only when its prefix appears in the text. With the other changes in this release, against v0.1.8 on an M1 Max: a one-request `-p` run uses 24% less CPU (19.6 to 14.9 ms), 64% less in a project's first session (48.3 to 17.2 ms), and each request in a 40-turn session 41% less (2.9 to 1.7 ms). Chanto's own peak memory drops 13-19%, though the whole process tree's peak in a session without Bash rises about 2 MB: the login shell that captures your shell setup now starts during the first reply.
- **Shell secrets no longer left on disk.** To set up Bash commands, Chanto captures your shell's exported variables. The snapshot it builds from them always left secrets out, but the raw capture, tokens included, stayed next to it under `~/.chanto/shell-snapshots` for two days. It is now deleted as soon as it has been read, and captures left by earlier versions are removed at the next start.
- **Grep without ripgrep matches ripgrep.** On a machine without ripgrep, Grep's built-in search now prints what ripgrep would: no `--` between plain matches, `--` between context groups across files as well as within one, no empty line after a file's final newline, no file name when searching a single file, and a `glob` that overrides ignore files.
- **No waiting for MCP servers.** The full-screen and `--plain` sessions show their prompt without waiting for MCP servers to connect, which could take up to 10 s for an imported server and 30 s for a configured one. `/mcp` lists them as connecting, and the first request waits for any still connecting, so it has their tools. A run started with a prompt, such as `-p`, still waits at launch. The tools for MCP resources now also appear when a server connects later, for example after `/mcp login`.
- **`/model` switches at once.** Switching models no longer waits on a slow or unreachable provider for the new model's details: vision support is assumed until the next request, which waits for the answer. Switching before the first request no longer applies the previous model's context size and vision support afterwards.

## v0.1.8 (October 28, 2026)

- **Smaller install.** The release binary is about 21% smaller (25.7 to 20.3 MB on Apple Silicon): Chanto's own code is now optimized for size, like its dependencies, while the search and text crates stay optimized for speed. Startup and per-request CPU and peak memory are unchanged or slightly lower.
- **Faster file search in big repositories.** Grep's default `files_with_matches` mode lets ripgrep search on every core again and sorts the matching files newest first itself: ripgrep's own `--sortr=modified` made it search on one thread. Listing the files that mention `MODULE_DESCRIPTION` in the Linux kernel (97,000 files) went from 8-21 s to 3.4 s, in the same order.
- **Adaptive effort keeps the prompt cache.** Adaptive effort now changes the reasoning effort at most once a turn: the turn opens at the provider's default, and from the first reply that only called tools every later call in that turn asks for `low`, even after a reply with text. Switching between `low` and the default on every call made providers such as DeepSeek re-read the whole history uncached, 31% of uncached input in SWE benchmark runs.
- **Off-task searching.** Chanto works from the code in the working directory and its own dependencies instead of hunting for a ready-made fix on the disk, in package caches, other checkouts or the project's upstream history. A call that searches outside the project (`find /`, `grep -r ~`, `pip download`, `git fsck --lost-found`) still runs, and its result carries a short note steering back to the project. In benchmark sessions such searches were 18% of all calls.
- **Activated virtualenvs on macOS.** Bash commands run with the venv Chanto was started in first on PATH again. The shell snapshot took PATH's order from the login shell, whose `path_helper` puts the system directories first, so `python3` and `pytest` resolved to `/usr/local/bin` instead of the venv, and test runs failed for missing packages.
- **DeepSeek V4's context window.** `deepseek/deepseek-flash` and the other V4 models are budgeted at their 1M-token window instead of 128K, so long sessions compact far less often. DeepSeek's model list doesn't report a window, so Chanto had fallen back to its default.
- **License notices in every download.** Release archives, the npm packages, Homebrew installs and the container image now include `LICENSE`, `NOTICE` and `THIRD_PARTY_LICENSES.txt`, the license of every open-source crate built into the binary.
- **Language servers in large projects.** In a project with more than 20,000 files, reading a file no longer starts a language server; the first edit does. clangd runs there only with a compilation database (`compile_commands.json`, `compile_flags.txt` or `.clangd`): without one it guessed each file's flags, started one server per directory with a Makefile, and on the Linux kernel used about 500 MB for diagnostics that were mostly noise. Smaller projects are unchanged.
- **Jump to latest.** Scrolled up in full-screen mode, a pill on the transcript's bottom row says how many new lines arrived below (`↓ 12 new lines · click or esc`); a click on it, or esc, jumps back to the latest output.
- **Interrupting a turn stops its command.** A Bash command running when the turn was interrupted (Esc, Ctrl+C, SIGTERM) was left running about half the time, along with everything it started, even after Chanto exited. It is now stopped like a command that times out.

## v0.1.7 (October 27, 2026)

- **Auto-mode approvals.** Approving a file edit no longer switches auto mode into accept-edits mode, which caused subsequent commands to ask again. The safety classifier sees up to 16 recent user messages and is instructed to recognize explicitly authorized publishing, merging and deployment while respecting later restrictions. Static permission prompts explain which boundary needs approval.

- **Startup.** The secret patterns compile on the background warm-up thread while the rest of startup runs, instead of on the first prompt. A one-shot `-p` run against a local model drops from about 24 ms to about 19 ms of CPU, with no change to what is masked.
- **Browser.** Chanto's Chrome no longer tells pages it is automated: `navigator.webdriver` stays false even though Chanto has Chrome choose the debugging port, and a headless session reports the user agent the same build uses with a window. Sites see an ordinary Chrome.
- **Blocked calls.** A summary Chanto writes for a refused call opens with a label (`Blocked:`, `Error:`); only that label is coloured as a failure now, so the advice after it reads as prose instead of a wall of red.
- **Dropped responses.** A reply cut off mid-stream — the server or a proxy resetting the connection — now says so and what to do, instead of ending the turn with the HTTP client's `error decoding response body: … connection reset` chain.
- **Upgrade notices.** A newer release is announced on the startup screen — the cached answer appears immediately, without waiting on the network, and names the command that upgrades this install (`brew upgrade chanto`, `cargo install …`, `chanto upgrade`). A session that outlives a release checks again every half hour and reminds you once when one ships mid-conversation. `--plain` sessions now show the notice at the prompt instead of only once at exit.

## v0.1.6 (October 26, 2026)

- **Clickable links.** In full-screen mode, a click on a visible web link opens it in your browser even when the terminal does not support OSC 8. Wrapped URLs keep their full destination, and links in provider notices, user messages and subagent transcripts work too. Dragging still selects text; non-web schemes and control characters are rejected.
- **Quieter status area.** Background jobs use short descriptions and bounded command previews. The footer avoids repeating the provider and branch, hides healthy MCP connections, and shows `awake` only when idle.
- **Security: an apostrophe inside double quotes could hide command substitutions.** Prefix allow rules such as `Bash(echo:*)` could miss substitutions after quoted text containing an apostrophe. The permission check now keeps single and double quote state separate. Found by fuzzing.
- **UI regression tests.** Deterministic text and style snapshots cover 72 terminal frames across common UI states, widths and themes. CI publishes a PNG/GIF preview gallery for review.

- **Usage limits.** The footer shows the most-used reported quota window, its local reset time and `/usage`, dropping extra details on narrow terminals. A heads-up appears once at 25% and 10% remaining and re-arms after a window resets. Missing quota data is never estimated.

- **Background command status.** Output polls show the originating command’s description alongside its id, explain when they are waiting for new output, distinguish quiet/running/completed/failed jobs, and preview the latest three short lines. Failed background exits are marked as errors.

- **Tool messages.** A blocked call or other summary Chanto wrote shows its inline code styled, the way replies do, instead of literal backticks. Output that carries colour and diffs is still rendered as ANSI.
- **Working.** The status line says "Working…" instead of "Thinking…", and a highlight sweeps across the verb every 1.4s so a slow model call reads as moving before anything streams. Reduced motion and themes without RGB colours keep the flat accent.
- **Todo panel.** A long todo is cut at a word with an ellipsis instead of being clipped mid-word by the frame, the panel says `… N more` when more than eight are hidden, its height reserves every row it draws, a blank row separates the list from a running turn's status line, and the header lines up with the transcript.
- **Provider errors.** An error streamed by the provider now shows its own explanation and code instead of a bare `API error error:`. Providers nest the detail under `error`; a bare string, or an event with no detail, is shown as it arrives.
- **Interrupted sessions.** The notice shown when a session resumes after an interrupted turn lists the calls it was running one per line, instead of joining a batch of long commands into one run-on sentence.
- **Provider safety messages.** Refusal explanations and links now appear in streamed replies and transcripts. A provider safety filter that supplies no explanation shows a clear notice, and filtered turns end without retries or tool execution.
- **Streaming and large requests.** Stream framing borrows complete lines and compacts once per network read, avoiding per-line allocations and repeated buffer shifts. Buffered model request retries share the serialized body instead of copying it. The standard 40-turn overhead benchmark shows no measurable CPU or peak-memory improvement from these changes.

- **Container image.** Each release now publishes `ghcr.io/chanto-sh/chanto:<version>` and `:latest` for linux/amd64 and linux/arm64, built from the release's own signed Linux binaries, with build provenance and a cosign signature. See [Container image](docs/reference.md#container-image).
- **Security: secrets could reach the model through side calls and leave through run logs.** Compaction summaries, prompt and agent hooks, the permission classifier and other side requests sent the conversation unmasked; every model request is now masked in one place. Background runs' event logs, stream-json output, the web UI and `/remote` (including permission prompts, transcripts and the queue) and what a runner sends its server (including script output) are masked too, and on Unix run records and logs under `~/.chanto/runs` are now readable only by you. Background runs also mask their source checkout's `.env` values, sign-in and MCP OAuth tokens are masked once used, and plain `*_KEY` variables are withheld from commands (list one in `[secrets] pass_env` if a tool needs it) and masked when their value looks random. On Linux, Chanto's process is no longer readable through `/proc` by the commands it starts, so `gdb -p` and `strace -p` need root.
- **Security: the auto-mode classifier only counts what you typed as your request.** Prompts that Chanto or another agent wrote were shown to it as yours. This covered subagent tasks, goal, team and outcome steps, background run tasks and reports, slash-command expansions, and files attached to a prompt. A model could write "the user approved this" and get its own action cleared. Those prompts are now labelled as the agent's task. Files, resources and `<system-reminder>` context are cut from what you typed.
- **Security: tighter auto-mode classifier settings.** An untrusted project can no longer set `classifier_model` or `optimize.token_classifier`. The one-token fast path allows an action only when `ALLOW` is the top token with at least 90% probability; a prefix like `All` doesn't count.
- **Security: safe-listed commands could run programs or write files without a prompt.** Examples: `fd -x`, `find -fprint`, `git fetch --upload-pack` or `git fetch <url>`, `git grep -O`, `sort -o`/`--compress-program`, `rg --pre`, `tar --checkpoint-action`/`-I`, `git rebase -x`, `go build -o`, `go env -w`, `cargo --config`. The same was possible with `$'…'` quoting or brace expansion. These options now need approval in default mode and are vetted in auto mode too.
- **Security: shell writes to protected files ask in every mode but bypass.** Writing `.git/`, `.chanto/`, `.claude/` settings, `.mcp.json`, `.husky/` or `.vscode/` from the shell now asks, as an Edit of them does. That includes writes through redirections, `tee`, `cp`, `sed -i`, `curl -o`, `git config`, `sh -c`, a symlink made in the same command, or a target the shell computes (`$var`, `$(…)`). In auto mode, extracting an archive or applying a patch (`tar x`, `unzip`, `patch`, `git apply`) asks, because the input names the files written.
- **Security:** the auto-mode fast path sends inline code (`python -c`, `node -e`), remote packages (`npx owner/repo`, `go run host/x@v`) and option files (`curl -K`) to the classifier. MCP tools marked read-only now ask or go to the classifier like other MCP tools, unless an allow rule covers them.
- **Fix:** the permission check read `$$'…'` (the shell's PID followed by a quote) as `$'…'` quoting, so it could misjudge where a quote ended. Found by fuzzing.
- **Security: a prompt the model scheduled could run a shell command without asking.** A `CronCreate` prompt starting with `!` ran outside the sandbox when it fired, and one starting with `/` ran a slash command. Scheduled prompts, background reports and undelivered messages now always reach the model as plain text (no `!`, `/`, `#` or `@file`), `CronCreate` asks for approval outside bypass mode, and a command's arguments reach its `` !`cmd` `` blocks only as data.
- **Security: an imported session could turn on bypass mode.** `chanto import-session` now drops the file's settings, pull-request links, parent and dates, a resumed session never restores bypass mode, and a managed `defaultMode` wins on resume.
- **Security:** an approved call is refused if an earlier call in the same batch re-pointed its path through a symlink or made its command reach a secret file; the model's saves to user memory (loaded in every project) ask first and show what they store; installing a plugin asks when its skills or commands run `` !`cmd` `` blocks, register hooks or pre-approve tools, and git-cloned plugins with symlinks are refused.
- **Security: checks ran outside the sandbox with your full environment.** Verified-mode, goal, outcome and team checks and formatters run commands the project defines (`npm test`, `pytest`), which the agent or a cloned repository can change. They now run in the sandbox like the agent's Bash commands, without secret-named environment variables; a check that needs a token gets it through `[secrets] pass_env`. Language servers start without secret-named variables, and detecting pytest no longer imports a `pytest.py` from the project.
- **Security: git that Chanto runs itself could run programs a repository's config names.** The startup status and log, the TUI's branch, `/diff`, and git for worktrees, background runs and teams now turn off the fsmonitor hook, hooks, signing, diff, filter and merge drivers the repository defines (Git LFS keeps working) and submodules, and never follow a worktree's `.git` file. File tools ask before writing a `.git` file, as they did for the `.git` directory.
- **Security: runners ran a server's scripts unsandboxed.** `chanto runner connect` now runs the scripts jobs come with only with `--allow-scripts`, sandboxed and without the machine's secrets, and checks the run ids it's given.
- **Security: `chanto runs apply --on` trusted the server's branch and base.** It now only creates the run's own `chanto/run/<id>` branch, never moves an existing one, and requires the base to be a commit your checkout has.

## v0.1.5 (October 25, 2026)

- **Security: the install scripts check the release signature before trusting anything.** `install.sh` read the version for "latest" from an unsigned `SHA256SUMS`, skipped the signature for v0.1.0/v0.1.1, and skipped it entirely without OpenSSL 3 (as on stock macOS); `install.ps1` never checked it. Both now verify the signature first, with OpenSSL 3 or, from this release on, with `ssh-keygen` against a new `SHA256SUMS.sshsig`, and stop if neither tool is available. They refuse releases before v0.1.2, which aren't signed, and refuse a "latest" older than v0.1.5. See [Verifying a release](docs/reference.md#verifying-a-release).
- **Terminal:** fix “The cursor position could not be read within a normal duration” on startup, focus restoration, and return from an external editor. Fullscreen redraws no longer require a cursor-position response from the terminal.

## v0.1.4 (October 23, 2026)

- **Security: commands could slip past the permission check.** A heredoc closed by a marker bash doesn't accept (such as one indented with spaces), or characters that ended a word for Chanto's check but not for bash, let a command after them run without a prompt. Chanto now ends heredocs and words exactly where bash does. Please update: `chanto upgrade`, `brew upgrade chanto`, `npm i -g @chanto/cli` or `cargo install chanto --locked`.
- **Security: the cloud metadata address could skip its approval.** `169.254.169.254` written with a tab, `%`-escapes, a trailing dot or control characters wasn't recognised, so a request to it went through without asking. Chanto now checks the address as the URL parser reads it.
- **Security:** hosts like `localhost.evil.com` no longer count as local for plain HTTP, and GitLab, Slack, Google and SendGrid tokens ending in `-` are now redacted whole. These and the fixes above were found by fuzzing, which now runs on every pull request.
- **Faster and lighter.** About a third less CPU per turn and about 15% less peak memory in our overhead benchmark: Chanto no longer starts helper processes it doesn't need (`defaults`, `caffeinate`, git outside a repository), stops rewriting and re-reading files on every model call, sends requests without building a copy of the conversation first, and skips work whose result hasn't changed.
- **Releases** now carry each build's SLSA provenance as a `.intoto.jsonl` file next to the archive.

## v0.1.3 (October 23, 2026)

- **Windows: unchanged `--worktree` sessions are cleaned up again.** Chanto exited while still inside the worktree, and a file held open for a moment could make the removal fail, so an untouched worktree was kept and reported as having changes. Chanto now leaves the worktree first and retries; if removal still fails, it says so rather than claiming there are changes.
- **`chanto migrate`:** when nothing in the other agent's configuration maps to Chanto's, the empty result is no longer misread as a setting.
- **Release process:** crates.io packages are now published without a stored token (trusted publishing), and each release workflow job gets only the permissions it needs.

## v0.1.2 (October 23, 2026)

- **Signed releases.** From this release on, each release's `SHA256SUMS` is signed with the project's release key. `chanto upgrade` refuses a release whose signature is missing or wrong, and `install.sh` checks it too whenever OpenSSL 3 is available. To verify a download yourself, see [Verifying a release](docs/reference.md#verifying-a-release).

## v0.1.1 (October 23, 2026)

- **Security: commands could be hidden from the permission check.** A quote that bash reads as plain text, in a comment (`# don't`), a heredoc body or after a backslash, made Chanto's safe-command check misjudge where a quote ended, so the commands after it skipped the check and ran without a prompt. The check now reads comments, heredoc bodies and escapes the way bash does. Please update: `chanto upgrade`, `brew upgrade chanto`, `npm i -g @chanto/cli` or `cargo install chanto --locked`.
